# Uno Work Companion

Расширение, через которое браузерная версия Uno Work действует **во вкладках самого пользователя** — в сессиях, куда он уже залогинен. Пароли и куки никуда не передаются: агент шлёт команды, браузер их исполняет локально.

## Зачем оно нужно

Вкладка не может управлять другой вкладкой — это модель безопасности браузера, и разрешениями со страницы это не обходится. Поэтому у нас три исполнителя browser-команд:

| Исполнитель               | Где выполняется       | Когда нужен                          |
| ------------------------- | --------------------- | ------------------------------------ |
| Electron webview          | десктопное приложение | десктоп, панель предпросмотра        |
| headless Chromium в боксе | машина юзера/бокс     | автономные задачи, ноут закрыт       |
| **это расширение**        | браузер юзера         | нужны его логины, его IP, его сессии |

## Модель доступа

Агент видит только:

- вкладки, которые **сам открыл** (`openUrl` создаёт вкладку и она попадает в список);
- вкладки, которые юзер **явно расшарил** кнопкой в попапе.

Всё остальное в браузере ему не видно. Список расшаренных вкладок живёт в `chrome.storage.session` — очищается вместе с сессией браузера. Вкладка выпадает из списка при закрытии, а кнопка «Stop sharing all tabs» отзывает доступ мгновенно.

Команда `evaluate` **не поддерживается намеренно**: выполнение произвольного кода из сети — это RCE-вектор и почти гарантированный отказ на ревью. Поддержаны `state`, `openUrl`, `navigate`, `reload`, `back`, `forward`, `click`, `clickText`, `type`, `press`, `screenshot`. Все действия в странице — статически объявленные функции через `chrome.scripting.executeScript({ func })`, не строки кода.

Host-разрешения объявлены как **optional** и запрашиваются только когда юзер первый раз жмёт «Share the current tab» — до этого расширение не имеет доступа ни к одному сайту.

## Транспорт

```
страница work-*.uno4.dev  ──window.postMessage──►  content.js  ──chrome.runtime──►  background.js
        ▲                                                                                  │
        └──────────────────── результат тем же путём ◄─────────────────────────────────────┘
```

Content script инжектится только на origin'ы Uno Work (см. `content_scripts.matches`). ID расширения странице знать не нужно.

## Локальная установка (сейчас)

1. `chrome://extensions` → включить **Developer mode**.
2. **Load unpacked** → выбрать эту папку.
3. Открыть Uno Work в браузере — расширение объявит себя автоматически.

Для локального демона на другом порту допиши его в `content_scripts.matches`.

## Как публиковать — и обязательна ли модерация

Коротко: **для массовой раздачи — да, модерация обязательна**, но есть три легальных пути, и первый мы можем использовать уже завтра.

### 1. Unlisted в Chrome Web Store — рекомендую для старта

Расширение проходит ревью, но **не появляется в поиске**: ставится только по прямой ссылке, которую мы даём из консоли.

- разовый взнос разработчика — $5;
- срок ревью — обычно часы–пара дней; расширения с `tabs` + `scripting` попадают в углублённую проверку;
- нужен приватный policy-документ и внятное объяснение, зачем нужны разрешения;
- обновления доставляются автоматически, ID стабильный.

Чек-лист подачи (всё, кроме первых двух пунктов, уже сделано в коде):

- [ ] аккаунт разработчика Chrome Web Store — $5 разово, верификация почты;
- [ ] политика приватности на публичном URL (например `uno4.dev/privacy/extension`);
- [ ] иконки 48/128 — ✅ в папке;
- [ ] скриншоты 1280×800 (2–5 штук) и короткое описание — снять с рабочего флоу;
- [ ] обоснования разрешений и single-purpose — черновики ниже;
- [ ] не запрашивать host-разрешения при установке — ✅ они optional;
- [ ] никакого удалённого кода — ✅ нет `eval`, нет `evaluate`, инжекты только статическими функциями;
- [ ] выбрать видимость **Unlisted** и забрать прямую ссылку для консоли.

Что подготовить к подаче:

- **Single purpose**: «выполнять действия в расшаренных пользователем вкладках по команде из приложения Uno Work»;
- обоснование каждого разрешения (`tabs` — знать URL/заголовок целевой вкладки; `scripting` — клик и ввод; optional host permissions — только по явному действию юзера);
- политика приватности на публичном URL (что не собираем данные, не продаём, не шлём содержимое страниц третьим лицам);
- скринкаст сценария — ревьюеры это любят и он снимает половину вопросов.

Главный риск отказа — «remote code execution». Поэтому в коде нет `eval`, нет загрузки скриптов извне, нет `evaluate`, а все инжекты — статические функции. Это надо явно написать в заявке.

### 2. Enterprise-политика (для команд с управляемым Chrome)

Речь про корпоративный сценарий: у компании есть Google Workspace или управляемые Chrome-браузеры, и её админ раскатывает расширения политикой на все машины сотрудников — те не нажимают ничего.

Два подварианта:

- **force-install из Web Store** (в том числе unlisted) — по-прежнему требует, чтобы расширение было опубликовано, зато сотрудники ничего не устанавливают;
- **self-hosted CRX**: свой `update_url`, политика `ExtensionSettings` с `installation_mode: force_installed` — Web Store не нужен вообще, но работает **только** на браузерах под управлением этой компании.

Что важно понимать: обычный пользователь так поставить расширение не может. Chrome с 2018 закрыл установку CRX со сторонних сайтов на Windows и macOS. Для розницы остаётся Web Store либо developer mode.

### 3. Unpacked / developer mode

Работает сразу, без модерации, но: юзер должен включить developer mode, Chrome регулярно показывает предупреждение, а обновления придётся ставить руками. Годится для нас, ранних клиентов и демо — не годится как продуктовый путь.

**Firefox** (AMO) — отдельная подача, ревью тоже есть, но манифест совместим почти без правок. **Safari** требует упаковки в приложение Xcode и Apple Developer Program — оставляем на потом.

### Flow для юзера, к которому идём

1. В браузерной версии Uno Work агенту нужно что-то сделать в браузере → появляется плашка «Подключить этот браузер».
2. Кнопка ведёт на нашу страницу установки → Chrome Web Store (unlisted link) → «Установить».
3. Возврат в приложение: расширение уже объявило себя, плашка сменилась на «Браузер подключён».
4. При первом действии в уже открытой странице — «Share the current tab» в попапе (один клик, один запрос разрешений).

То есть ровно две кнопки: «Установить» и «Расшарить вкладку».
