# 22 — Workspace заново + безопасный «Continue on machine»

Статус: решения приняты (Миша, квиз 15.09.2026), реализация не начата. База — ветка
`feat/sidebar-v2-port` (0.0.56: агентские треды + сайдбар-список чатов).

## Что есть сейчас (разбор кода 15.09)

- Workspace живёт в SQLite каждого демона одной строкой (миграция 038: «демон ровно в
  одном workspace»), id генерится демоном сам → каждая машина = отдельный workspace.
  Join/merge нет. Grants/claims/policy/`scope:"repositories"` нигде не проверяются, peer-команды
  сервер не порождает. Реально работают только instruction layers и подписи машин.
- Сайдбар: «все машины» (Labs `allMachinesSidebar`, scope `all`) = все подключённые окружения,
  без фильтра по workspace; scope `active` = одна машина, внимание с других машин не видно.
  Один репозиторий на двух машинах склеивается в проект по `repositoryIdentity.canonicalKey`,
  треды — отдельные карточки с чипом машины. Цвета машин — из клиентских настроек, не из registry.
- Continue (0.0.53, `apps/web/src/continueOnMachine.ts`, `apps/server/src/.../threadContinue.ts`,
  `continueTransport.ts`): снапшот рабочего дерева (tracked+untracked) → force-push `--no-verify`
  в `origin` ветку `uno/continue/<threadId>` → цель fetch + `restoreCheckpoint` как незакоммиченный
  diff поверх ТЕКУЩЕЙ ветки, без worktree. Без git/remote — не работает. Проект на цели ищется по
  remote, иначе клонируется. `.env` из корня (не из worktree) копируется по умолчанию через RPC.
  История — текстовый seed 40×4000 символов.

## Решения

1. **Workspace = набор проектов и/или машин + общие правила и/или секреты.**
   - Участник workspace — проект (логический, по canonicalKey; с перечнем машин, где он разрешён)
     или машина целиком (все её проекты).
   - Одна машина и один проект могут входить в несколько workspace.
   - Общие правила = instruction layers (уже есть как концепция) → применяются к тредам проектов
     workspace на любой машине.
   - Общие секреты = env-переменные workspace → доступны харнессам тредов этого workspace
     (через тот же механизм, что `.env`/secrets-endpoint; значения не в чат и не в логи).
   - «Только одна машина» = workspace из одной машины (пресет «Только этот компьютер»).
2. **Хранение — аккаунт Uno** (синк между устройствами и веб-версией). Нужен API в консоли/
   бэкенде аккаунта: CRUD workspace, участники, правила, секреты (секреты — шифрованно, выдача
   только демонам аккаунта). Серверный registry на демонах (038) дальше не развивать; миграцию
   данных не нужно — там нечего сохранять кроме подписей машин.
3. **Сайдбар:** переключатель workspace в футере; список = треды проектов/машин текущего workspace
   со всех машин; у других workspace — счётчик «ждут тебя». Фильтр проекта сверху — внутри
   workspace.
4. **Continue — безопасно:**
   - снапшот передаётся через приложение (source daemon → клиент → target daemon, git bundle/
     tar поверх существующих аутентифицированных соединений), НЕ через `origin`/GitHub;
   - `.env` и секреты — только по явной галке, по умолчанию выключено; брать из worktree треда;
   - на цели — отдельная ветка/worktree `uno/continue/<thread>` от совпадающего base-коммита;
     если base нет на цели — fetch base из remote, иначе отказ с понятным текстом;
   - цель — машина, где проект есть (или предложить добавить его на эту машину), в рамках текущего
     workspace;
   - убрать force-push `--no-verify`; уборка временной ветки больше не нужна.

## Порядок работ (предложение)

1. Continue безопасный (самое срочное — уже в релизе 0.0.53+).
2. API workspace в аккаунте Uno + клиентская модель + сайдбар (переключатель, счётчики).
3. Общие правила (instruction layers из аккаунта) → харнессы.
4. Общие секреты workspace → харнессы.
