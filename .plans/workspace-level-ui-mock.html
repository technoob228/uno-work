Одна ось, четыре значения. Первый уровень — проект или компьютер; второй — либо ничего (тогда «другая» сущность показывается маркером на строке чата), либо вторая сущность подзаголовками. Сортировка применяется на каждом уровне отдельно: компьютеры — по активности / по имени / вручную; проекты — как сейчас; чаты — как сейчас.

Здоровьеотдельной точкой зелёный / жёлтый / серый — не смешивается с цветом
Цвет закрепляется за компьютером один раз и не переназначается при появлении или удалении других — иначе привычные чипы перекрашивались бы. Палитра прогнана валидатором: 3 оттенка проходят все жёсткие проверки в обеих темах, включая цветоаномалии. Фиолетовый не берём — он неотличим от синего при дейтеранопии и занят акцентом приложения.
Почему монограмма главная, а цвет вспомогательный. Так идентичность никогда не держится на одном цвете: при 5+ компьютерах оттенки кончаются, а буквы — нет. Полное имя остаётся в подсказке при наведении и в панели Workspace.
Вопрос: монограмма из 2 символов или разрешить до 3 («HK1», «PRD»)? И достаточно ли выбора из 3 цветов, или добавить ручной выбор из более широкой палитры с предупреждением о различимости?

1 · РепозиторийAGENTS.md из git · только чтение
Монорепозиторий bun+turbo. Всегда `bun run test`, никогда `bun test`. Перед готовностью: bun fmt · bun lint · bun typecheck.
2 · Workspaceиз манифеста · правится в правилах
Прод трогают только через заявку. Балансы и VPS клиентов — человек на гейте.
3 · Этот компьютерперекрывает workspace
Здесь нет AVX2 — Uno Code не запускается, использовать OpenCode через Uno Gateway. e2e гонять `bun run test:e2e:server` (headless, без Electron). Демон под systemd `t3-server.service` — после правок сервера обязательно rebuild + restart.
Слитый текст кладётся в .t3code/UNO_WORKSPACE.md (генерируется, в gitignore), а в AGENTS.md добавляются три строки-указатель между маркерами. Удалил маркеры — мы их не возвращаем. Твой текст вне маркеров не трогается никогда.
Порядок: репозиторий (git) → workspace (манифест) → компьютер (локально, перекрывает манифест). Четвёртый слой «проект» из v1 убрал — вернём, когда появится реальная нужда.
